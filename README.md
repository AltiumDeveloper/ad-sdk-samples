# Altium Designer SDK samples (C#)

152 complete Altium Designer extensions written in C#. A sample is a whole extension, not a snippet:
installation files, menus, a thin shim that Altium Designer loads, and an implementation you can edit while Altium
Designer runs. Copy one to start your own extension.

The samples are built for **Altium Designer 26.12** and its SDK assemblies (`Altium.SDK.dll`,
`Altium.SDK.Interfaces.dll`). The API reference is the
[Altium Designer SDK documentation](https://docs.developer.altium.com/ad-sdk-docs/).

## Requirements

* Windows, Altium Designer 26.12 (it hosts .NET 10)
* .NET 10 SDK
* Windows PowerShell 5.1 or PowerShell 7 for the scripts in `tools/`, Node.js 22 for `tools/*.mjs`

## Getting started

1. Copy `local.props.example` to `local.props` and set `AltiumSystemDir` to the `System` folder of your Altium
   Designer installation. The build references the SDK assemblies from there.
2. Build everything: `dotnet build AdSdkSamples.slnx` (Debug), or one sample's folder.
3. Deploy a sample: `.\tools\deploy.ps1 -Sample BoardUniqueId`, then restart Altium Designer once. Its menu appears.
4. Run a command from its menu, or from a terminal through the sample's development pipe:
   `.\tools\ad.ps1 -Sample BoardUniqueId run GetUniqueId`. (An extension starts on first use: run one of its menu
   items once after Altium Designer starts.)
5. Edit the implementation and run `.\tools\dev.ps1 -Sample BoardUniqueId`: it rebuilds, Altium Designer reloads the
   new code in place, and the command runs. No redeploy and no restart, unless you change the shim or the
   installation files. `.\tools\undeploy.ps1 -Sample BoardUniqueId` removes a deployed sample.

`tools\deploy.ps1 -Configuration Release` installs a sample the way you would ship it: no development pipe, no hot
reload.

## How a sample is put together

```
samples/<category>/<Name>/
  <Name>/                 the shim: the server module Altium Designer loads, panels, notification handlers
    Installation/         <Name>.ins (commands, panels, document kinds), <Name>.rcs (menus), <Name>.out (outputers)
  <Name>.Impl/            the implementation: one class per area, [HotCommand] methods, reloaded on every build
  README.md               what it shows, how to run it, how it works, notes
  sample.json             the same facts for tools: title, summary, facets, search phrasings, commands
```

The shared code under `framework/` (the shim's server module and command routing, the implementation's command
context, panel hosting) and the build files `Directory.Build.props` / `Directory.Build.targets` come from the
[Altium Designer extension template](https://github.com/AltiumDeveloper/ad-extension-template).
`node tools/new-sample.mjs` creates a new sample from the same template.

Samples marked "restart" in the index add a panel, a context menu, a notification handler, an outputer or a document
kind, which Altium Designer loads at startup: deploy them and restart Altium Designer before you try them.

## Metadata

Every `sample.json` follows [`schema/sample.schema.json`](schema/sample.schema.json): a title and summary, three
facets with closed vocabularies — **domain** (where in Altium Designer), **task** (what it does), **surface** (how it
hooks in) — search phrasings and the commands.

From those files and the compiled code, CI builds the samples index
([`schema/index.schema.json`](schema/index.schema.json)): every SDK type and member each sample uses, with file and
line, and the reverse index from each SDK type and member to the samples that use it. The Altium Designer SDK
documentation is built from it.

Contributing: [AGENTS.md](AGENTS.md) has the rules for samples, READMEs and metadata. After adding or changing a
sample, run `node eng/build-index.mjs`: it checks every `sample.json` and updates the table below.
